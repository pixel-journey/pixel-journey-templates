# CONTRIBUTING.md

**Contributing to Pixel Journey**

Thank you for helping build the Pixel Journey ecosystem. This document explains how to contribute effectively while keeping everything consistent, educational, and aligned with our shared principles.

## Before You Start

1. Read the root `README.md` — it explains the purpose of this handbook and the overall philosophy.
2. Review `STANDARDS.md` — these are the non-negotiable rules and expected shapes for all Px work.
3. Skim `PATTERNS.md` — understand the recommended approaches for common problems.
4. Check `ECOSYSTEM.md` — see where your contribution fits in the bigger picture.

## Types of Contributions We Welcome

- Improving or expanding standards and patterns in this handbook
- Adding new pattern overviews when you discover reusable approaches in your work
- Enhancing documentation clarity and educational value
- Fixing inconsistencies across repos that violate the standards
- Proposing new high-value patterns that multiple Px projects could benefit from
- Improving GitHub templates, issue/PR flows, or contribution hygiene

## Contribution Process

1. **Open an issue first** (recommended for larger changes) — describe the problem or new pattern and link to relevant sections.
2. **Fork & branch** from `main`.
3. **Follow the Standards** — every change must align with the Foundational Principles and expected repository shape.
4. **Update documentation** — if your work introduces or refines a reusable pattern, document it here so others benefit.
5. **Write clear, educational commit messages** and PR descriptions.
6. **Request review** — at least one maintainer should review for standards alignment and educational quality.

## Documentation Quality Bar

We aim for extremely high educational standards:
- Layered explanations (big picture → specific decisions → implementation notes)
- Clear "Why" sections for architectural choices
- Decision matrices or trade-off discussions where relevant
- Examples of best expected usage
- Links to related patterns or repos

If you're unsure how much documentation is enough, err on the side of more context. Future contributors (and AI agents) will thank you.

## Code & Implementation Contributions

While this particular repo focuses on standards and patterns, implementation work happens across the wider organization:
- Follow the patterns documented here
- Align with `pixel-journey-design-system` for all UI work
- Use WharfKit exclusively
- Maintain the educational quality bar in every repo you touch

When a new reusable pattern emerges from real implementation work, bring it back to this handbook so the whole ecosystem benefits.

## Questions?

Open an issue or reach out in the Pixel Journey community channels. We're building this together.

**Thank you for helping make Pixel Journey consistent, trustworthy, and a joy to develop in.**
