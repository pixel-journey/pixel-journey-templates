# CONTRIBUTING.md

**How to Contribute to Pixel Journey**

Thank you for your interest in contributing to Pixel Journey! This document outlines the process and expectations for contributions.

## Before You Start

1. Read the root `README.md` to understand the vision and principles.
2. Review `STANDARDS.md` — these are the non-negotiable rules.
3. Familiarize yourself with `PATTERNS.md` — these are the recommended approaches for common problems.
4. Check `ECOSYSTEM.md` and `GLOSSARY.md` if you're new to the project.

## Contribution Process

1. **Fork & Branch** — Create a feature branch from `main`.
2. **Follow Standards** — Ensure your work aligns with the 7 Foundational Principles and expected repository shape.
3. **Use Patterns** — Leverage existing patterns from `PATTERNS.md` where applicable.
4. **Document** — Add or update educational documentation (layered explanations, examples, rationale).
5. **Test** — Ensure linting, TypeScript checks, and builds pass.
6. **Submit PR** — Use the PR template. It includes a checklist referencing this handbook.

## AI-Assisted Contributions

We encourage the use of specialized AI personas from `ai-prompts/`. When using them:
- Pair with relevant knowledge banks when available.
- Review outputs against the standards in this handbook.
- Clearly note in the PR description if significant portions were AI-generated.

## Review Expectations

Reviewers will check for:
- Alignment with Foundational Principles
- Use of recommended patterns
- Educational documentation quality
- Design system consistency (where applicable)
- Overall clarity and maintainability

## Questions?

- For general questions, open a GitHub Discussion or reach out to the core team.
- For help learning the ecosystem, try the `educational-support-bot.md` persona.

We appreciate high-quality, educational contributions that help move the Pixel Journey ecosystem forward. Welcome aboard!
